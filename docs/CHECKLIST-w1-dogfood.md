## 1. 焦點文法（SPEC §2）

### 1.1 ← 回側欄、↑↓ 走列

挑一組**至少 12 張**的群組（連拍或相似照片都行），這樣格線一定會有好幾列。

| # | 按什麼 | 應該看到 |
|---|---|---|
| 1.1.1 | 在側欄按 `→` | 進入格線，焦點（白色虛線框）落在保留張上 |
| 1.1.2 | 一直按 `→` 到第二列 | 焦點一張一張往右走，換行後繼續 |
| 1.1.3 | 在第二列某張上按 `↑` | 焦點跳到**正上方那一張**（同一個水平位置），不是「前一張」 |
| 1.1.4 | 再按 `↓` | 回到原來那張（或同水平位置最近的那張） |
| 1.1.5 | 在**第一列**按 `↑` | **什麼都不動**（不會跳到側欄、不會繞到最後一張） |
| 1.1.6 | 在**最後一列**按 `↓` | 什麼都不動 |
| 1.1.7 | 一直按 `←` 到**第一張**，再按一次 `←` | 焦點回到側欄，而且是**原來那一列**（選取的群組沒有變） |
| 1.1.8 | 把視窗拉窄一半，重做 1.1.3 | ↑ 仍然是「正上方那一張」——列變窄了，答案跟著變 |

> 🔬 1.1.3 是這一波最容易做錯的一條：舊版四個方向鍵都是 ±1，↑ 看起來「有動」但動的是前一張。
> 判準是**視覺上正上方**，不是「有沒有反應」。

### 1.2 Return 改成打開預覽、K 接手「留下這一張」

| # | 按什麼 | 應該看到 |
|---|---|---|
| 1.2.1 | 格線裡任一張上按 `⏎` | **打開放大鏡**（預覽），保留張沒有換人 |
| 1.2.2 | 在放大鏡裡按 `⏎` | **什麼都不會發生**，也不會「叮」一聲 |
| 1.2.3 | 按 `空白` | 關閉放大鏡，焦點還在同一張 |
| 1.2.4 | 再按 `空白` | 又打開（開／關同一鍵，跟 Finder 一樣） |
| 1.2.5 | 格線裡按 `3` | 第 3 張變成保留張（綠框 ★），焦點跟著過去 |
| 1.2.6 | 按 `A` | 整群保留 |
| 1.2.7 | 焦點移到任一張，按 `K` | **那一張**變成保留張（綠框 ★），**焦點不動**、也不會開預覽 |
| 1.2.8 | 找一組**超過 9 張**的，把焦點移到第 12 張，按 `K` | 第 12 張變成保留張——這就是 `K` 存在的理由（1–9 到不了那裡） |
| 1.2.9 | 放大鏡裡按 `K` | 當前這張變成保留張，放大鏡不關 |
| 1.2.10 | 對一張**已經劃掉**的按 `K` | 它同時被取消劃掉並變成保留張（`promote` 本來就會 un-reject——K 只會讓刪除變少，不會變多） |
| 1.2.11 | 對一張**受保護**（★最愛／✎編輯過／文件）的按 `K` | **正常變成保留張**，不會跳「受保護」提示。見下方說明 |

| 1.2.12 | 對一張**最愛**按 `⇧X` 強制標刪（確認），此時群組標題列會出現琥珀色的「已包含受保護」按鈕；接著對**那一張**按 `K` | 標記取消、它變成保留張，而且**那顆琥珀按鈕消失**（不會留著一個沒東西可描述的舊狀態，審查 P3-1）。若這組還有**另一張**被強制標刪的受保護張，按鈕**應該留著** |

> ✅ 1.2.8 就是上一版報告裡那個取捨，現在補起來了：`K` ＝「留下焦點這一張」，跟按它的 1–9 號碼完全同一件事，而且沒有號碼限制。
>
> ✅ **已由審查裁定：`K` 不擋是對的**（審查 §0(a) 逐條同意），以下理由留著給下一輪紅隊看——
> ① `LibraryModel.promote()` 本來就沒有任何保護閘（`LibraryModel.swift:1245-1251`），所以 1–9 從來不擋；擋 K 就不再是「跟 1–9 同一件事」。
> ② X 被擋是因為 X **會刪**，而那些張不准刪；K 是**留**，留下一張受保護的照片正是保護存在的目的——`KeeperReason.favorite` 還是七個理由裡的第一優先，也就是說「加星的那張通常就是要留的那張」。擋掉 K 等於讓**最常見的那個指定動作**在鍵盤上做不到。
> ③ 被擋時會跳的那句提示寫的是「受保護 —— ⇧X 強制標刪」，拿它來回答一個「我要留下這張」的請求是答非所問。
> 審查同時指出我原本的不變式寫得太強（「K 只會讓刪除變少」），已改成「`promote` 從不加入 `rejected`」，並補上 P3-1 那一行（見 1.2.12）。
